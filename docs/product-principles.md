# Pathwise 产品原则

## 用户问题

Pathwise 服务正在从校园走向职场、但不知道下一段经历该如何选择的年轻人。核心痛点不是“缺少一份建议”，而是简历、项目、面试反馈持续变化后，用户无法判断这些新事实是否改变了可投岗位、关键缺口与行动顺序。

## 产品承诺

每一份真实经历都进入同一条职业路径：画像决定方向，规划给出当前唯一优先行动，成果成为证据，证据再改变岗位判断与后续路线。AI 必须解释变化，不能只重新生成一屏文字。

## 北极星指标

**有效职业行动完成率** = 留下成果或外部反馈的已完成行动数 / 已开始行动数。

只勾选任务不算完整完成。成果可以是项目链接、量化结果、面试反馈、作品或其他可复核材料。该指标同时约束行动质量、指导可执行性和用户正反馈。

## 核心漏斗

| 指标 | 定义 | 页面责任 |
| --- | --- | --- |
| 首份规划完成率 | 建立画像后成功得到有效规划的用户 / 开始建立画像的用户 | 首次上传简历后确认目标；失败时保留输入并可重试 |
| 有效职业行动完成率 | 有成果的完成行动 / 已开始行动 | “今日规划”只突出一个行动；指导给出完成标准；完成后立即收成果 |
| 7 日有效证据新增率 | 7 日内新增至少一份有效证据的活跃用户 / 活跃用户 | “进展与成长”统一承接简历、项目、面试和行动成果 |
| 证据导致计划调整率 | 改变现实岗位、首要缺口或首行动的证据 / 新增证据 | 每份证据显示它改变了什么；未改也明确说明判断得到增强 |

## 信息层级

1. 首屏回答“这是什么”和“最近发生了什么”。
2. 今日规划只回答“现在唯一先做什么、为什么”。
3. 岗位判断回答“现在能去哪、毕业能去哪”。
4. 行动计划提供执行细节，不与今日规划争抢主 CTA。
5. 进展与成长按“输入事实 → 看见路径变化 → 获得成长反馈”排列。
6. 案例、RAG 来源和匹配解释按需展开，不能打断行动主线。

## 功能取舍

- 优先做：证据影响解释、行动完成标准、失败可恢复、规划版本变化、明确的单一下一步。
- 谨慎做：情绪陪伴、游戏化和地图动效；只有能提高有效行动完成率才保留。
- 不做：按点击数涨进度、为了丰富而增加孤立 AI 工具、重复展示同一个下一步、把简历全文铺在页面中。

## 可观测方案

当前前端在本地 `pathwiseProductEvents` 中记录以下事件，不上传个人内容：

- `profile_submitted`：是否首次画像、是否有经历摘要。
- `plan_completed`：规划来源，以及岗位/缺口/首行动是否变化。
- `action_started`：行动名称及从清单或指导页开始。
- `action_committed`：用户主动选定的当前行动及 AI 估算天数；承诺本身不增加进度。
- `evidence_added`：证据类型、是否带文件、是否导致规划变化。
- `effective_action_completed`：关联行动、是否带成果链接、成果文字长度。
- `growth_summary_copied`：已验证行动数，以及摘要是否包含一次可解释的路径变化。

事件仅保存最近 300 条。后续接入正式分析平台时，只上传枚举和布尔属性，不上传简历、成果正文、目标岗位或文件名。

## 7 日回访机制

不使用泛提醒或连续签到。用户在行动指导中主动“设为当前行动”，系统依据 AI 的投入估算生成预计完成日。回访时今日规划仍聚焦这项行动并显示剩余时间；用户确认完成后立即回收成果，成果进入证据链并触发路径重算。行动承诺不计进度，只有执行事实和成果才能推进路径。
