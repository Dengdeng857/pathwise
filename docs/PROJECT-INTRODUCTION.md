# Pathwise 项目介绍

> 面向用户、潜在贡献者与商业合作方的公开说明

## 一句话定位

Pathwise 是一个以真实证据驱动路线变化的职业成长操作系统：它帮助大学生看清自己距离理想职业还有哪几步，并把每一步变成可执行、可验证、会影响下一步的行动。

## 为什么需要 Pathwise

大学生并不缺少“职业建议”，缺少的是一条能随现实进展更新的路。传统测评通常只在第一次填写问卷时给出结论；通用 ChatBot 能生成漂亮文字，却不会可靠地记住项目、简历和面试反馈如何改变岗位判断。结果是：

- 不知道当前背景能投什么、毕业时能到什么位置；
- 知道缺口，却不知道今天先补哪一个；
- 做完项目或经历面试后，无法判断这条新证据是否改变了路线；
- 进度容易被“打卡次数”伪造，真正的成果没有沉淀成职业资产。

Pathwise 把职业规划从一次性回答变成连续的决策循环，让每次真实经历都回答三个问题：发生了什么？路线哪里变了？现在最值得做什么？

## 竞品空白与 Pathwise 解决的需求

Pathwise 不试图替代已有工具，而是补上它们之间缺失的“连续职业决策层”：

| 常见工具 | 通常擅长什么 | 常见空白 | Pathwise 的补位 |
| --- | --- | --- | --- |
| 职业测评 | 通过问卷给出兴趣、性格或方向建议 | 结论往往停留在一次测评，难以随项目和反馈更新 | 将画像与持续证据关联，记录判断为何改变 |
| 招聘/投递工具 | 找岗位、筛选职位、追踪投递 | 关注岗位与流程，不负责补齐能力缺口和行动顺序 | 把“当前可投、毕业可达、差距”转成下一步行动 |
| 通用 AI Chat | 快速回答问题、生成简历或建议 | 对长期状态、证据来源和前后版本缺少结构化记忆 | 用 Plan、Evidence、Trajectory 状态保存连续变化，并让 AI 解释变化 |
| 学习打卡/课程平台 | 提供课程内容、练习和完成记录 | 完成课程不等于形成岗位证据，学习与求职路线可能脱节 | 以成果和外部反馈作为进度依据，把学习结果接回岗位判断 |

Pathwise 的核心补位可以概括为：**证据 → 判断 → 行动 → 路线重算**。它不承诺替用户做出最终职业选择，也不把匹配度当成录取概率；它帮助用户理解新事实带来的影响，并把当前最重要的差距变成一项可执行、可验证的行动。

## 核心主线闭环

```text
事实输入 → 结构化证据 → 岗位判断 → 唯一优先行动
    ↑                                      ↓
成果/面试反馈 ← 可验证证据链 ← 完成行动并提交成果
                     ↓
                  路线重算
```

用户可以上传简历或建立基础画像，确认目标方向后得到三层结果：现在可投、毕业可达、当前差距。系统把最关键的差距压缩成一个“今日规划”，提供短步骤、预计投入和完成标准。用户设为当前行动，完成后提交作品链接、量化结果或面试反馈；新证据进入证据链，并触发岗位匹配、缺口和后续行动的重新判断。

核心原则是“承诺不等于进度”：勾选小步骤只代表正在执行，只有执行事实与可复核成果才会推进路径。

## 产品体验

Pathwise 的体验借鉴初代多邻国的清晰节奏，但服务对象从语言学习换成职业成长：

1. **低门槛开始**：首次打开是诚实的空状态，用户可填写画像或上传材料，不用接受预设身份。
2. **一次只做一件事**：今日规划只突出一个优先行动，避免把用户淹没在长建议里。
3. **短步骤反馈**：行动指导拆成可勾选的小步骤，展示投入、完成标准和当前执行进度。
4. **成果才算升级**：提交真实成果后，系统说明它缩小了哪个缺口、增强了哪项岗位证据。
5. **地图与报告讲清变化**：地图展示主路线、补证支线和有原因的岗位分岔；成长报告保留“证据 → 判断变化 → 下一步”的连续记录。
6. **移动端可用**：核心工作台、行动抽屉、地图和报告采用响应式布局，保证窄屏阅读与操作。

## 价值验证指标与用户收益

Pathwise 用可观察的行为和证据验证价值，不用生成字数、卡片数量或虚构就业结果作为成功标准：

- **首份规划完成率**：建立画像后得到有效规划的用户 / 开始建立画像的用户，验证首次体验是否真正产出路线。
- **有效职业行动完成率**：带成果证明的完成行动 / 已开始行动，验证建议是否能转化为真实执行。
- **7 日有效证据新增率**：7 日内新增至少一份有效证据的活跃用户 / 活跃用户，验证产品是否帮助用户持续积累职业资产。
- **证据导致计划调整率**：改变岗位、首要缺口或首行动的证据 / 新增证据，验证系统是否真的理解并利用新事实。

对用户的直接收益是：更清楚当前能投什么、更明确距离目标还差什么、更容易决定今天先做什么，并能在项目、作品或面试反馈发生后看到路线变化的原因。上述收益需要通过真实使用和脱敏案例持续验证，不代表就业、录取或薪资结果保证。

## 算法与状态模型

Pathwise 采用“确定性状态模型 + AI 解释”的边界：

- **Plan**：画像、岗位范围、差距、行动指导和三阶段路径的结构化规划；
- **Evidence**：简历、项目、行动成果、面试反馈等事实，记录来源、时间、类型与影响；
- **Trajectory**：规划版本之间的变化，说明岗位、首要缺口或首行动是否改变；
- **Commitment**：用户主动设定的当前行动与预计完成日；承诺本身不增加进度；
- **Weighted progress**：按行动难度、预计投入和成果质量加权，不按卡片数量或点击数增长；
- **Map feedback**：里程碑只有在有意义的成果或外部反馈后才解锁。

AI 用于从用户事实中提出岗位候选、解释匹配原因、生成行动指导和总结证据影响；规则模型负责 schema 校验、进度计算、状态迁移与路径分叉。这样既保留自然语言的理解能力，又避免让模型静默地替用户决定目标或凭空增加进度。

## 隐私与可靠性

隐私是产品信任的前提，而不是发布后的补丁：

- 默认将用户状态保存在当前浏览器 `localStorage`；一键重置只清理本地 Pathwise 数据。
- 前端只调用同源 `/api/*`；API Key 仅允许存在本地 `.env` 或 Cloudflare Secret，绝不进入浏览器或 Git。
- 证据流展示结构化摘要与变化，不把简历全文铺在进展页面；公开案例使用脱敏合成数据。
- AI 输出必须满足 JSON schema、长度与占位符检查；失败时保留上一次有效规划并走本地规则降级。
- 服务端与 Cloudflare Pages Functions 均提供健康检查、输入校验、超时保护和错误回退。

## 技术架构

Pathwise 是可本地运行、可静态部署的轻量 Web 应用：

| 层次 | 当前实现 |
| --- | --- |
| 核心界面 | `career.html` / `career.js`：画像、规划、行动、成果闭环 |
| 视觉系统 | `redesign.css`、`report.css`：响应式工作台、地图与成长报告 |
| 状态与算法 | `path-model.js`、`continuity-model.mjs`、`commitment-model.js`、`game-feedback-model.js` |
| 本地服务 | `server.py`：静态服务器、AI 代理、材料解析与规则降级 |
| 云端部署 | `functions/api/`：Cloudflare Pages Functions，同源 API |
| 质量保障 | `tests/`：模型、API、UI、隐私、无障碍和发布 smoke；`npm test` 一键回归 |

无模型 Key 时仍可使用本地规划与行动指导完成完整体验，便于用户和贡献者 clone 后快速了解产品。

## 产品亮点

**问题真实**：聚焦大学生从校园到职场的连续决策，而非泛化的“AI 职业测评”。

**主线完整**：从事实输入到成果证据再到路线重算，所有页面都服务于同一条成长路径。

**可解释**：岗位匹配、进度和地图变化都能说明依据；用户知道为什么改道，而不是只看到新分数。

**AI 有边界**：模型负责理解与解释，确定性代码负责关键状态，降低幻觉和不可复现风险。

**可验证**：北极星指标是“有效职业行动完成率”——有成果证明的完成行动数 / 已开始行动数。

**可体验**：三分钟内可完成“建画像 → 得规划 → 设行动 → 交成果 → 看路线变化”的闭环，地图与成长报告把抽象价值变成可见变化。

## 商业化潜力

Pathwise 采用“开源核心建立信任，专业服务创造收入”的路径：

- **个人 Pro**：多目标路线、版本对比、可选模型、导出与加密同步；
- **学校与训练营工作台**：班级匿名进度、导师批注、证据模板和群体缺口分析，不暴露个人原文；
- **企业与 API**：岗位能力模型、候选人自评与成长建议接口，明确定位为辅助决策，不自动淘汰候选人；
- **生态服务**：本地化主题、Evidence adapters、私有部署与评测服务。

商业指标将围绕激活、有效行动完成、7 日有效证据新增和付费留存，而不是模型调用量。学生能够先获得无 Key 的可用产品，机构再为更强的协作、同步和治理能力付费。

## 开源与 GitHub 传播路径

Pathwise 的开源增长依赖可复现的产品价值，而非口号：

1. 保持 clone 后 10 分钟内可运行，并提供 deterministic demo mode、90 秒演示和清晰的部署文档。
2. 公开匿名合成案例、架构图、隐私说明、评测样例与版本 changelog，让别人能复现“证据导致路线变化”。
3. 提供 `good first issue`、贡献规范、主题包和本地化入口，降低非核心开发者的参与成本。
4. 通过可分享的成长摘要传播真实行动与路线变化，而不是虚构分数或夸大的就业承诺。

长期开源影响力目标是 GitHub 10,000+ Stars；前提是产品可用性、安装成功率、文档质量、持续发布和社区响应同时达标，不刷量、不提交个人材料、不用未经验证的宣传数据。

## 3 分钟演示脚本

**0:00–0:30，提出问题。** 展示空工作台：“职业建议通常只认识你一次；Pathwise 关注的是项目和面试反馈之后，下一步是否应该改变。”

**0:30–1:10，建立路径。** 上传脱敏简历，确认目标岗位，展示现在可投、毕业可达和关键差距；停在唯一的今日行动。

**1:10–1:45，开始行动。** 打开行动指导，展示短步骤、预计投入和完成标准，点击“设为当前行动”。说明承诺不会虚增进度。

**1:45–2:30，提交成果。** 输入一条项目成果与链接，提交后展示证据摘要、岗位判断变化和前后规划版本。

**2:30–2:50，展示连续性。** 添加一条面试反馈，打开地图和成长报告，指出主路线、补证支线及分岔原因随证据变化。

**2:50–3:00，收束。** 复制成长摘要：“Pathwise 的核心不是更长的回答，而是让每一次真实经历，都能改变下一步。”

## 当前边界

Pathwise 当前是可运行原型，不应被描述为自动求职、录取预测或专业咨询替代品。岗位匹配分数是基于输入证据的匹配度，不是录取概率；AI 结果仍可能出错，需要用户确认。当前数据主要保存在浏览器本地，跨设备同步、多人协作、正式分析平台和大规模岗位数据尚未完成。材料解析能力也会因部署环境而异，公开体验应使用脱敏或合成内容。

## 下一步

下一阶段优先把“证据原生”做深：统一 Evidence schema，让每个岗位判断都能回溯到证据句；让地图、成长报告和行动指导共享同一状态；补齐本地服务与 Cloudflare Functions 的契约测试、流式截断和错误可恢复体验。随后再推进个人 Pro、学校工作台、企业 API 与插件化材料适配器。

欢迎贡献代码、测试、匿名合成案例、行业岗位模型、无障碍改进和本地化文档。所有贡献都应回答同一个问题：它让用户更清楚地知道，距离理想职业还差哪一步，以及现在如何迈出这一步？
